# 开发及算法说明

## 技术结构

- Phaser 4.0.0 负责校园绘制、指针输入、雨滴粒子和昼夜画面。
- TypeScript 核心规则是纯函数，不依赖 Phaser Scene 或 DOM。
- Vite 8.3.5 提供本地开发服务器与静态构建；Vitest 5.1.0 运行确定性测试；Playwright 1.64.1 驱动已安装的 Chrome/Edge 做浏览器验收。
- 预算、成本、概率、时长、评分和建筑名称集中在 `src/config/gameConfig.ts`。

## 随机地图

地图生成以 `mapSeed` 初始化 Mulberry32 风格的 32 位伪随机数发生器。道路由 20 个正交相邻格组成，随机选择 0—3 个转弯，并限制每段方向与长度。建筑入口从道路旁合法空格选取，建设候选位置过滤越界、道路和建筑占用。生成结果通过长度、连通、无重格、转弯数量、建筑入口唯一性和操作位覆盖数校验；最多重试 80 次，极少数失败时使用合法直线路线，并在 Board 的 `fallbackUsed` 标记回退。

道路贴图按上下左右邻接 bitmask 判为端点、直路、转角或交叉。当前生成器不产生交叉，但贴图函数保留交叉类别以便处理邻接。

## 建设交易

每次建设先以坐标去重，再检查不同设施冲突、相同设施复用和可用预算。费用只按真正新增的对象收取。历史记录只存储本次创建的设施位置或棚的建筑 ID，因此撤销不会删除前一操作共用的对象。建设阶段以外的购买、撤销、清空与新地图操作均被锁定。

树木与绿化的外观变体随设施保存，但放置冲突、费用、舒适度、安全度和积水计算只读取设施功能类别。建筑外观保存在建筑状态中，不加入事件随机数、预算或模拟输入；建设阶段以外锁定。

## 天气、积水与事故

事件使用独立于 `mapSeed` 的 `eventSeed`。每轮先抽取时段和天气，逐步计算各道路格与建筑入口水量快照；同一格对草坪和排水口的覆盖判断均为布尔值。事故只从最终水量快照抽样，每个普通道路格和每个建筑入口最多各抽一次。雨滴动画使用 Phaser 自身粒子器，不消耗数值随机数。

`simulateChallenge` 在开始挑战时纯函数生成全部五轮报告，动画只读取每轮 8 个水量快照，跳过动画直接展示已生成的结果。因此动画快慢不会改变结果。

## 主要入口

- 游戏入口：`src/main.ts`
- 配置：`src/config/gameConfig.ts`
- 地图：`src/core/mapGenerator.ts`
- 建设：`src/core/placement.ts`
- 水量：`src/core/water.ts`
- 事故与安全度：`src/core/accident.ts`
- 五轮模拟：`src/core/simulation.ts`
- Phaser 场景：`src/scenes/CampusScene.ts`
- DOM 控制器：`src/ui/uiController.ts`
- 单元测试：`tests/*.test.ts`

## V4.3 视觉层与坐标

逻辑地图固定32×18，建设组固定8组。buildingLayout为建筑选择包含自身锚点、避开道路与候选格的1／2／3格显示区域，分别使用16／32／48像素源图按2倍显示。牌匾使用完整校园名称，字体按可用空间调整。

相机围绕道路、候选格、建筑与牌匾边界适配实际容器，Phaser Scale.RESIZE跟随窗口。鼠标通过camera.getWorldPoint反算逻辑格；浏览器测试通过相机matrixCombined正向映射点击点。测试注入的场景访问入口仅存在于测试服务器，生产包没有测试全局变量。

装饰是Board派生的独立集合，局部视觉哈希不调用地图或事件SeededRandom。背景和夜色向逻辑地图外延伸，雨滴范围跟随相机。水面读取原waterFrames，不重新模拟。预算、概率、吸排水、安全、舒适、评分和五轮状态机均未改动。
